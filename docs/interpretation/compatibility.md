# 解讀來源與觀察資料相容契約

## 版本責任

排盤規則、解讀內容、觀察 payload 與加密備份 payload 使用不同的版本。
`BirthProfile` 維持公曆 local components 與 IANA 時區，不把農曆輸入草稿加入持久化契約。
解讀內容版本 `1` 對應目前 App 的五個 baseline 與十四主星落宮規則，並不表示專家審閱完成。
新增來源卡不改變既有 seed ID 或 meaning，不改寫既有排盤結果。

來源查詢分開以下狀態：

- 已知目前版本：可對照 App 內規則、seed IDs 與 facts，但仍須顯示人工審閱的真實狀態。
- 已知歷史版本：只能以該版本的內容與來源解釋歷史紀錄，不套用新含義。
- 未保存版本：保留文字與原始 IDs，顯示「來源版本未保存」，不推定當時內容。
- 未知版本或未知 ID：顯示不可核對的限制，不回填最新規則或繼續個人化推論。

來源卡不能把段落引用契約誤述為 AI 每句語意已獲證明。
新收藏與新保存對話輪次必須保存當時解讀內容版本，並在備份與 CloudKit payload 往返時保留收藏版本。
收藏及已保存對話缺少版本時維持既有 legacy 狀態，不能因新增來源 UI 回溯認證。

## 新觀察與回顧

`SavedObservation` 保存使用者主動選取的單段快照及初始想法。
快照包括當時文字、來源類型、內容版本或缺少版本狀態、已知 ruleset、seed meanings 與 facts。
只在資料確實可核對時保存目前版本，不能對外部匯入的未知文字補造 provenance。
`SavedObservationReview` 以獨立 UUID 記錄後續觀察，不覆寫起始內容。
回顧分為符合、不符合、尚無法判斷，不生成準確率或命理效度結論。

同一 UUID 對應的不可變快照若有不同內容，須明確拒絕衝突，不以較新時間靜默覆蓋。
不同 UUID 的回顧可以並存，重試同一筆資料不能建立重複紀錄。
歷史快照不是可執行規則；還原或同步不能使它成為目前 builder 的 facts 或 seeds。
使用者可刪除觀察與回顧，刪除觀察須處理全部子回顧與提醒。
刪除命盤須處理關聯觀察、回顧、提醒及導覽進度，不能留下可再同步復活的子資料。

## 本機、備份與同步矩陣

| 來源 | 目標／動作 | 必須成立的結果 |
| --- | --- | --- |
| 現行舊 SwiftData store | 新 App 首次開啟 | 遷移保留命盤、筆記、收藏、對話與 tombstones，新觀察集合為空；失敗保留原 store。 |
| 備份 v1 | 新 App 還原 | 缺少 seed IDs 時遷移為空，不補造來源版本。 |
| 備份 v2 | 新 App 還原 | 保留 seed-fact evidence，沒有快照集合不代表要刪除現有新觀察。 |
| 備份 v3 | 新 App 還原 | 先驗證全部命盤／觀察／回顧引用、版本、唯一 ID 與不可變內容，再原子套用。 |
| 備份 v3 | 舊 App 還原 | 舊 App 安全拒絕不支援版本，不靜默移除新欄位。 |
| 未知備份版本 | 新 App 還原 | 拒絕；不得把缺欄位猜成舊 schema。 |
| 不完整或衝突備份 | 新 App 還原 | 拒絕且保留本機原內容與有效提醒，不進行部分覆寫。 |
| 舊裝置修改原筆記或收藏 | 新 App 同步 | 不更動獨立的觀察快照或回顧。 |
| 舊裝置刪除父命盤 | 新 App 同步 | 父 tombstone 套用至新觀察與回顧，不留下孤兒資料。 |
| 新裝置新增兩筆不同回顧 | 另一新裝置同步 | 依不同 UUID 保留兩筆，不依 `updatedAt` 擇一丟棄。 |
| 同一觀察／回顧重試 | CloudKit | 以固定 UUID 冪等寫入，不產生重複。 |
| 新觀察／回顧刪除 | 舊 App 同步 | 使用獨立刪除 record type，舊 App 不需解析未知實體種類。 |
| 未同意新資料同步 | 任意同步或 App 前景重試 | 不查詢或寫入新增觀察 record types，既有同步仍可獨立使用。 |
| 觀察同步部分遠端失敗 | 新 App | 保留已同意狀態、有效本機資料與明確失敗訊息，不宣稱遠端無變更。 |

此矩陣定義必須驗證的契約，不代表所有列項已通過；實際證據追蹤於五項功能計畫。

## 隱私與外部影響

新的觀察同步使用獨立同意狀態與資料揭露，不沿用舊版同步開關推定同意。
關閉同步只停止後續傳送，不宣稱已移除遠端內容。
觀察可以本機保存及主動加密備份，不需先登入 iCloud 或設定 AI。
提醒權限拒絕或排程失敗不得造成已編輯觀察內容遺失。
API key、endpoint、完整對話與衍生命盤 cache 不進入新備份。
私人快照與回顧不進入 AI prompt、命盤分享、Widget 或診斷紀錄。
新模型與 CloudKit 路徑須以合成測試資料驗證，不能自行使用他人的出生資料或既有私人 CloudKit 作為測試沙箱。

## 復原界線

不能以安裝舊 App 直接開啟新 store 作為已驗證的降版方案。
停用新入口時仍保留歷史資料的閱讀與明確刪除能力。
遷移／還原失敗不以空白資料庫取代原資料，不假定 SQLite sidecar 可省略。
CloudKit 部分寫入不具跨 record 的自動復原保證，使用固定 ID、不可變資料檢查與 tombstones 處理重試。
新規則遭停用時仍須保留歷史來源狀態，不重寫已保存的快照。
